# 学校适配指南

本项目采用“共享认证核心 + 每校 / 校区规则”，不是爬遍所有学校后按固定网页坐标填密码。学校的管理中心、统一身份登录和实际联网认证可能是不同站点。

## 1. 先确认现状

尽量提供当前官方网络中心指南、发布日期、校区和实际 Wi-Fi 名称。比对旧项目时要检查旧入口是否停用、是否只是自助平台，以及账号使用何种已开通服务。校外打不开内网网关通常不能据此判定地址失效。

## 2. 收集不含私人信息的页面特征

在本人的校内设备上记录登录页结构、输入框属性、协议框、运营商选项、成功与失败码，以及跳转是否需要本次终端参数。提交时删除输入值、Cookie、IP / MAC、完整查询参数和学校账号。不要发送密码或未经处理的 HAR。

`scripts/collect-campus.ps1` 目前只适用于该脚本明确列出的三个原型，不是通用学校采集器。它的输出也不代表认证已通过。

## 3. 实现规则与核心

- 浏览器规则在 `adapters/<id>.json` 中声明可信来源、发现入口、DOM 选择器、服务映射和页面校验。
- 相同认证厂商也可能有不同版本；HTTP 协议和安全校验需要在 C# 注册表与 Node 核心同步实现，不能只添加任意 JSON。
- `SchoolRegistry.cs` 和 `school-rules.mjs` 验证规则及可执行入口。加入新来源要说明官方依据，不能为省事扩大到任意域名。
- 新学校先 `enabled: false`。未知页面、来源歧义或缺少网关上下文时停止，避免把密码提交到不明页面。

## 4. 隔离测试

使用虚构账号和本地响应，覆盖动态跳转、表单版本、账号拒绝、服务不匹配、超时、验证码、来源变化及外网失败。网络命令必须替换；默认测试不得修改真实 Wi-Fi 或调用学校认证。

现有 `build-snnu-trial.ps1`、`build-school-trial.ps1` 和 `build-sam-trial.ps1` 可生成隔离试验包。它们只供维护与校内验收，包含 Node 等依赖，首次没有账号或已启用任务。修改核心后应重新核对试验包清单，不能仅凭打包成功判为可用。

## 5. 校内验收

由本人使用已开通服务的账号，在能本地操作的情况下测试。先确认真正未认证；仅打开网页或原会话免密登录不算密码认证验收。核对是否实际提交密码、外网能否访问、Windows 到点是否真正执行，以及没有目标 Wi-Fi 时是否保留其他网络。

反馈学校、校区、程序版本、时间、结果码、是否开启无感 / TUN 即可；不要贴真实凭据。现场验收前，规则保持默认关闭。[验收边界](../VERIFICATION.md)
